# doc-mine

把一個專案的知識挖出來,寫成 `docs/` 下分類的 Markdown。**每一句都有據**:句尾標來源,標不出來就標 `[UNVERIFIED]`。開工前先訪談使用者,問到他說「開始」。

## 核心原則:有據

敘述的依據只有三種——專案裡的檔案、官方文件、實際執行結果。命名、慣例、「通常是這樣」只是**線索**,拿來找證據用;找不到證據就寫 `[UNVERIFIED]` 並說明缺什麼。**寧可留白,不補猜。**

證據標記放在句尾,一句一個;一句有兩個主張就拆成兩句:

| 標記 | 來源 | 例 |
|---|---|---|
| `[src: <path>:<line>]` | 專案內的檔案(原始碼、README、config) | `[src: src/main.rs:42]` |
| `[doc: <URL>]` | 官方網站、官方文件 | `[doc: https://example.com/docs/cli]` |
| `[run: <指令>]` | 實際執行過,指令和輸出一起貼進文件 | `[run: rtk --version]` |
| `[UNVERIFIED]` | 三種都沒有,括號寫缺什麼 | `[UNVERIFIED](找不到寫入邏輯)` |

## 步驟 0 — 快速掃一眼(不深讀)

讀 README 和頂層目錄,目的只有一個:讓訪談問得出具體的東西(「這裡有 A、B、C 三個模組,哪個最想懂?」)。完成條件:能用一兩句說出這專案是什麼、分哪幾塊。

## 步驟 1 — 訪談(問到使用者說「開始」)

一輪最多兩題,等回答再問下一輪。使用者答「不知道」就記下、換下一題,不追問。使用者說「開始」(或 start、go、可以了)就停,進步驟 2。使用者一開始就說「直接開始」「不用問」→ 跳過訪談,步驟 4 不產出。

依序問這五題,再依回答追問:

1. 你目前怎麼理解它?一兩句就好。
2. 你用它做什麼?或打算拿來做什麼?
3. 哪部分最想搞清楚?(用步驟 0 看到的模組名具體問)
4. 有沒有你「覺得應該是這樣,但沒確認過」的?
5. 有沒有不需要整理的部分?

第 4 題的答案是**查證重點**:每一條都要在步驟 4 給出有據的對或錯。

完成條件:使用者說「開始」。把訪談整理成一段**訪談摘要**——認知、用途、重點、待驗證清單、排除清單——留給步驟 2 和步驟 4 用。

## 步驟 2 — 讀專案

**分工判準**:專案小(單一模組、幾十個檔案內)→ 主線自己讀,不派 agent。專案大 → 派 **2–4 個** subagent,**依程式碼區域分工**(頂層目錄、模組),一個 agent 一個區域。**硬上限 4 個**,派滿就不再派。

派工 prompt 必帶:

- 訪談摘要(agent 看不到主對話)
- 負責的區域路徑
- 證據標記表(上表原樣貼過去)
- 輸出契約:**條列筆記**,每條句尾帶標記,不寫成文章。待驗證清單裡屬於這區域的項目逐條回答。
- 一句:「自己讀完直接回報,不再派 agent。」

主線收齊筆記後才開始寫。完成條件:每個區域都有筆記;待驗證清單每條都有人回答,或明確回報找不到。

## 步驟 3 — 寫分類文件

一份文件一個主題,寫進 `docs/`(repo 已有文件慣例就跟它)。預設四類,依訪談增減——重點多的類拆細,使用者說不要的類跳過:

1. 技術原理 — 它怎麼運作
2. 應用場景 — 什麼時候用、怎麼搭配
3. 操作參考 — 指令、參數、設定
4. 設計取捨 — 為什麼這樣做,代價是什麼

`[run:]` 的地方,指令和輸出一起貼進文件。完成條件:每一句句尾都有標記。

## 步驟 4 — 訪談回應 `docs/00-answers.md`

一份獨立文件,排最前面,只回答訪談裡使用者提的東西:

- **你說的** — 訪談摘要
- **你問的** — 第 3 題逐項回答,附標記
- **你以為的 vs 實際上** — 第 4 題逐條:對就寫對,錯就寫實際上是什麼,都附標記;查不到就 `[UNVERIFIED]`

## 步驟 5 — 收尾驗證

1. `00-answers.md` 裡每個 `[src:]` 都實際開檔看那一行;其他文件每份抽 5 條開檔看。內容對不上就改敘述或改標記。
2. 列出所有 `[UNVERIFIED]` 給使用者,每條說缺什麼。
3. 回報文件寫在哪、共幾份、各是哪一類。

完成條件:驗過的 `[src:]` 全部對得上;`[UNVERIFIED]` 清單已回報。
